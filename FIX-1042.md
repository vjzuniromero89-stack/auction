# Cloudflare 1042 fix
The prior FREE-ONLY due-diligence route made an HTTP `fetch()` back into another API route on the same deployed Worker. Cloudflare returns error 1042 for Worker-to-Worker fetches on the same zone unless special routing/bindings are used.

v4.3 removes that network hop entirely. Both API routes import and call `runFreeResearch()` directly in the same Worker invocation. No compatibility flag or service binding is required.
